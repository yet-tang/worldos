# RFC 0025 — 中文世界内容与世界删除

## 状态

开发阶段实现。

## 问题

创世台界面已经中文化，但新世界的初始实体仍使用 `resident-001`、`river`、`farm` 等英文标识作为可见名称，导致正常观察界面仍混入开发标识。同时，多世界开发流程缺少删除自定义世界的能力。

## 决策

### 中文创世内容

新创建世界的可见世界内容默认使用中文：

- 地点使用中文名称，例如“农田”“集市”“河畔”“粮仓”。
- 居民使用确定性生成的中文姓名；内部角色标识使用“人物-001”形式，不再暴露 `resident-*`。
- 初始谣言、外部威胁和疾病名称使用中文。
- 资源键、事件类型和组件键继续保持稳定协议，由中文界面负责展示翻译，避免破坏 Runtime 语义。

同一 WorldConfig + 同一世界种子仍必须生成完全一致的初始事件。

### 删除世界

`WorldCatalog.delete(world_id)` 是世界删除的目录级入口：

- 仅允许删除 Creator 创建的独立世界。
- `first-living-world` 开发样板不可通过网页删除。
- 删除时移除 catalog 条目，并清理对应 SQLite 主文件和 WAL/SHM 辅助文件。
- 删除接口执行前获取与运行控制相同的单世界写锁；正在运行的世界返回冲突，不并发删除。
- “我的世界”页面必须二次确认后才发送删除请求。

## 验收

- 新建古代小镇的正常界面不再出现 `resident-*`、`farm`、`river` 等英文生成名称。
- 中文姓名和中文地点在重放后保持一致。
- 同配置同种子仍确定性一致。
- 自定义世界可从“我的世界”二次确认后删除。
- 删除后 catalog、SQLite、WAL、SHM 均不再包含该世界。
- 开发样板世界不能通过删除接口删除。
- 删除不会影响其他世界。
